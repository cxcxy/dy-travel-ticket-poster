# 布局感知的高级配色系统

本文件负责画布、票根纸面/信息联和文字的选择。`landscape` 默认三色从照片派生；`portrait` 无指定风格时整套采用参考图锁定色：`#92946E` 灰橄榄绿织物、首选 `#E8DECF` 暖象牙票纸、`#1B1811` 近黑油墨。用户明确要求竖版照片主色配色时才恢复三种颜色全部照片派生。

## 强制流程

1. 先确定 `layout` 与最终照片裁切，再在该裁切上取色：`landscape` 为 `774 × 507`，`portrait` 为 `472 × 748`。禁止直接统计带白边、黑边或无关区域的整张原图。
2. 运行 `suggest_palette.py`，为当前照片单独生成 JSON 和三套预览：

   ```bash
   python3 scripts/suggest_palette.py \
     --input source.jpg \
     --layout portrait \
     --palette-treatment auto \
     --photo-center-y 0.5 \
     --output-json palette.json \
     --preview palette-review.png
   ```

3. 同时用 `view_image` 查看原图、最终裁切和 `palette-review.png`。横版三套都必须看，`quiet-light` 只是默认候选；竖版的 `quiet-light` 是参考图精确首选，另外两套只改变暖纸深浅。
4. 记录最终采用的布局、配色处理、背景、票纸/信息联、文字 HEX，以及各自来源。`portrait-reference` 的三种颜色都写为参考图锁定来源；配色 JSON 中的 `layout` 必须和渲染、验证一致。
5. 横版若三套都不合格，调整裁切或排除错误来源区域后重新取色。竖版若参考配色被用户明确否定，再改用 `--palette-treatment photo-derived` 或用户指定色；不得暗中改默认。

## 取色边界

- 透明像素先安全铺为暖白，绝不读取 alpha 下隐藏的 RGB；候选分析再排除该近白铺底。默认清除与边缘相连、近乎纯色的白/黑装裱条；若它是作品内容，候选、渲染和验证三步都传 `--keep-neutral-borders`。
- 人像默认不从皮肤、头发或大面积服装生成整张背景；只有能证明该颜色也属于墙面、土地、木材、天空或水面等环境时才可使用。
- 背景来源色的面积通常至少占最终裁切 `3%`；信息联来源色通常至少占 `1.5%`。红车、黄楼、招牌等明确叙事重点可降低到 `0.5%`，但必须目视确认。
- 背景优先来自稳定环境色：天空、水面、墙面、道路、木材、植被或石材。信息联优先来自语义强调色或深色锚点。
- 保留来源色色相，只调整明度与色度；近中性色不强行染成彩色。

脚本对背景来源的排序依据为：`45% 面积 + 35% 裁切外缘环境占比 + 20% 低色度稳定度`。它只能提供候选，不能识别人脸、品牌或叙事情绪，因此最终选择必须目视完成。

## 背景角色

`landscape` 默认以及显式 `photo-matte` 使用的软区间：

- 优先保留照片环境主色的色相；HSL 明度限制在 `46–68%`，避免背景过暗、过白或脱离照片。
- HSL 饱和度为来源色约 `72%`，限制在 `16–56%`。这是克制柔和的降饱和，而非把照片主色统一压成灰调。
- 照片本身接近中性时允许低于该下限，但必须与信息联形成清楚层级，且不能显脏。

有明确照片证据时，可以使用叙事性色彩：

- 深调或浅调警告区：`L=0.45–0.64` 或 `L=0.78–0.84`。
- 强色警告区：`C=0.08–0.16`。
- 采用警告区方案时，在交付前说明来源和选择理由，例如“采用照片中的深湖蓝以保留夜景情绪”。

除非用户明确指定，禁止背景 HSL 明度低于 `46%`、高于 `68%` 或饱和度高于 `56%`。不要把旧规范的 HSL `S=6–20%、L=58–62%` 当作默认；它会把有明确照片证据的蓝、红、黄主色压得过灰。

`portrait-reference` 不受上述照片主色软区间约束。它使用固定画布基准 `#92946E`、细密横纵织纹与轻微左上亮/右下暗；票纸首选 `#E8DECF`，近黑油墨固定为 `#1B1811`。严格验收以背景底图文件 SHA-256、外露像素重建、票纸像素和文字对比为准。票纸仍必须与画布保持 `Delta OK >= 0.10`，文字对比仍须达到下述门槛。

## 信息联角色

以下规则用于 `landscape`，以及用户明确要求 `portrait --palette-treatment photo-derived` 时。竖版参考默认不执行照片派生信息联规则。

- 优先使用照片中的语义强调色，例如红车、黄楼、陶土立面；其次使用深色锚点，例如深湖水、墨绿门窗或咖啡吧台。
- 没有合适强调色时，使用背景同色相的深浅变化，明度差至少 `0.18`。
- 背景与信息联的 OKLab 距离 `Delta OK` 理想为 `0.14–0.38`，低于 `0.10` 必须换色，高于 `0.50` 需警惕两色互不相干。
- 两者相对亮度比建议至少 `1.25:1`。不足时，只有同时满足色相差至少 `45°`、至少一色 `C>=0.07`、`Delta OK>=0.15` 才可采用。
- 禁止信息联与背景都落在相近的灰粉、灰蓝或泥棕中间调；阴影不能替代颜色层级。

## 文字角色

1. 先比较暖白 `#F4F0E5` 和暖黑 `#202321`，选择与信息联对比更高者。
2. 生成目标为全部文字至少 `5:1`，给抗锯齿和压缩留余量。
3. 硬门槛为小号日期、编号、序列码 `4.5:1`；大标题单独使用不同颜色时至少 `3:1`。
4. 对比不足时保持信息联色相和色度，调整其明度；不要为迁就颜色而牺牲用户文字可读性。

`portrait-reference` 例外固定使用 `#1B1811`，并分别对三档暖票纸计算对比；三档都必须高于 `4.5:1`。

## 三套候选的目视选择

逐套回答以下问题；任何一项明确失败就换下一套：

- 背景是否退到照片之后，而不是先于主体被注意到？
- 背景是否来自环境，而不是皮肤、头发、白边或偶然装饰？
- 信息联是否一眼可从画布中分离，同时仍与照片属于同一色彩世界？
- 大面积留白是否安静、干净，没有泥灰、塑料亮色或廉价餐饮品牌感？
- 深红、亮黄、深蓝等强色是否服务照片叙事，而不是为了“醒目”？
- 与同批已选海报相比，是否误用了完全相同的默认色？来源真实相同时允许相近，但必须逐张确认。

优先级为：主体分离度 → 照片来源真实性 → 画布/信息联层级 → 场景情绪 → 批量多样性。不要只按单一数值最高来选。

## 最终像素要求

- `landscape` 默认画布为照片主色家族的细腻纸纹；`portrait` 默认画布为参考图灰橄榄绿织物、票根为暖象牙纸、文字为近黑油墨。两者都不得出现光斑、窗影、反光或无关图案。用户明确要求“纯色 / 无纹理”时，画布才为边到边单一纯色。
- 默认背景通过 `build_subtle_texture_background.py` 后交由 `render_ticket_poster.py` 或 `build_ticket_batch.py` 确定性写入；旧版纯色修正才使用 `normalize_reference_layout.py --background-color` 或 `recolor_existing_poster.py`。
- 分隔虚线默认使用画布 HEX，形成同色切穿效果；阴影颜色由画布色自动调和，禁止固定暖黑污染冷色方案。
- 最终运行 `validate_ticket_output.py --expected-background-color --expected-stub-color --expected-text-color --expected-title/--expected-title-line --expected-date --expected-number --expected-code --require-renderer-metadata`。严格模式必须从命令外部再次声明完整颜色与票面文字合同；目标 HEX、全部外露画布像素、信息联逐像素重建、透明通道、源哈希、裁切配方、字体身份、文字对比或背景/信息联硬下限任一失败都不得交付。
- 用户明确指定背景色时使用 `--palette-mode user-specified`；仍需满足指定色相、克制的纸纹或明确要求的纯色、目标 HEX 和文字对比，且要重新选择适配的信息联与文字色。
